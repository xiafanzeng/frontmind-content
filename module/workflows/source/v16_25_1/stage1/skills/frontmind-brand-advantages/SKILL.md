# 整理并确认写作优势

在品牌定位A完成后、Reference Pack完成和首次P0写作前使用。优势是用户要表达的选择理由；本环节不重新定位，也不额外建立事实认证或竞品证明流程。

## 系统先总结

读取已提供材料、已确认定位和用户补充，按客户为什么值得选择来概括要点。每条只需id、优势要点、客户价值、建议写法；参考材料/来源和适用产品范围有则列。保持模型自己的选材和表达空间，不规定优势数量，不让用户从空白开始总结。

用户可以直接补充自己的优势原话。不要把“支持租赁”和“首家可租”拆成额外审查，不设置证据评级、ready/hold或比较证明门槛。也不自行编造用户和材料未提供的额外证书、研究、数字和事实。

## C：用户确认写作素材

`run-agent --action advantages`准备本轮Prompt，实际调用Kimi Hosted high并下载JSON保存草案；prepare/submit仅保留显式合同导入兼容。结构化页面展示优势要点、客户价值、参考素材（有则列）和建议写法，提供确认排序、增删修改、补充原话、明确暂无优势等操作。

`confirm-advantages`按用户具体选择的顺序保存本版写作优势；确认项全部进入`usable_claims`，不另筛“可发布/不可发布”。C是写作素材确认，不是第三次定位审批。既有明确优势选择可记录原话，不要求重复确认。

## 直接进入写作，保留版本

P0使用本版优势；问题文章从中选与当前问题相关的要点，不强制每篇全写。实际作者Prompt必须收到选用的优势及建议写法，不能只把它们留在Reference Pack里。

优势确认存为`reference_pack/differentiation/snapshots/{snapshot_id}.json`。补充或修改优势只生成新的优势版本，不重做定位、不强制新建整个项目、不重写已完成P0。旧文章继续读取其已绑定优势版本，新文章使用新确认版本。

`register_statements`登记用户补充原话；`revise-advantages`只归档当前优势草稿/指针，保留原件、定位、旧优势版本和旧文章。新问答/信源导入也不触发定位重做。具体命令和字段以本轮prepare合同为准。

## 本版知识入口

优势输入为完整知识库正文、确认定位与用户补充；程序已经实际展开主题节点和原资料，不仅传事实摘要。直接整理优势并在C确认，不生成额外综合说明。P0逐项展开；问题文章在另一包按题选用。
