# FrontMind 通用内容 Workflow v16.8

本包是一套跨行业流程。输入当前客户的品牌、原始资料、问题与写作要求；不会自动使用台心客户的范围、篇幅或历史授权。模型配置沿用原包，不自动安装依赖或调用模型。

新版 P01 为单品牌自然品宣；新版 P02 为主品牌与自动选定的两家竞品，主品牌先介绍。新P0—P06每篇独立交付10个标题，前5个formal为正式标题组、后5个scenario为场景卖点组，使用 `frontmind-category-titles/4`。前组按文章体裁拟正式标题，后组从同一篇文章的场景或卖点切入；十项各有清楚的阅读入口，避免把高频词换序再写十遍。P0十项均包含当前品牌名；P01/P02默认不出现品牌或机构专名，用户明确标题要求优先；P03—P06沿用当前选题的对象命名，保留必要主体名字。新P01至P06共用准备、蓝图、初稿、全文编辑和自然文风验读，保留推荐、解决方案、新闻、对比与评价各自体裁。P0专用正文链及历史正文合同保持原状。

沿用v16.5自然写作合同，从准备与蓝图开始用产品、业务或事件的正向内容安排文章。全文编辑使用完整例文，可以改导语、整段、整节与结尾；允许口语、有限重复和不完全工整的新闻稿感觉。验读只看当前完整稿是否自然可发布，有具体阅读问题再由DeepSeek编辑完整候选，随后重新阅读全文，不限一次返工。没有事实审计、分数或检测脚本。

v16.4的完整文章池与定位传递、P01的金蝶和ThinkPad文风参考、两篇专项案例研究及P02三家规则均保留。v16.8只更新标题素材、拟题与整组编辑，正文链和模型路由保持原状。

2026-10-11例文配置：P01保留原两篇；P02—P06各用用户选定的一篇，单篇即可，不自动补第二篇。五篇分别为腾讯AI轻薄本推荐、搜狐同福模式、搜狐Osmo Pocket 3发布、头条苹果与华为比较、网易小米14 Pro体验。选择、原文链接与统计见[已选例文](resources/selected_pattern_examples_20261011/README.md)。新任务在原例文节点读取全文，采用纯文字，不插图、图注或配图占位。显式更换例文和原A/B入口继续保留，历史任务不自动重绑。

| 类型 | 新稿建议正文可见字符 |
|---|---:|
| P01 单主体推荐 | 3000—3600 |
| P02 多主体推荐 | 2200—3000 |
| P03 场景解决方案 | 3500—4500 |
| P04 事件新闻 | 2200—3000 |
| P05 点名对象对比 | 3500—4500 |
| P06 怎么样、好不好、值不值得选 | 4500—5500 |

这些区间参考所选正文的信息量，作为展开建议，不构成字数验收门禁。统计含小标题、标点、数字和英文，排除主标题、空白与Markdown格式，不等于纯汉字数。P06用具体特点与已有体验形成评价理由，直接回应题目中的评价和选择疑问。

## 通用运行入口

```bash
export FRONTMIND_PYTHON="${FRONTMIND_PYTHON:-python3}"
./scripts/frontmind preflight
./scripts/frontmind article --brand '当前品牌' --input '/绝对路径/当前客户资料' --question '当前正式问题' --job-dir '/绝对路径/新任务目录'
```

也可传 `--reference-pack '/绝对路径/现有资料包.zip'` 复用资料包。若包内已有监控问题目录，可不传问题，在现有选题页面选择。新单问题任务需要本题本期两个不同 AI 平台的完整答案及逐条引用信源；Pack 已有的数据直接复用，只补缺失部分。运行环境需要 requirements.txt 内的依赖；预检缺依赖时报告，不自动安装。实际执行会使用 config 中已配置的模型与网关。

新单问题任务：选择问题并复用／补齐本题研究输入 → 答案分析与文章类型选择 → 在原例文页查看文章池、选择构思参考及原有文风方案 → 适用的定位（P02两家自动选定）→ 案例研究及编辑准备 → 正式蓝图 → 初稿 → 全文编辑 → 自然文风验读（需要时全文修订后再读）→ 独立标题 → Word、Markdown与标题表。P03至P06不增加逐题定位确认。

## 本题答案、信源与文章池

答案和信源必须属于同一问题、同一期次。缺答案或缺信源时，程序停在现有问题研究输入页，不开始答案分析或写作；不能搜索其他文章来代替本题引用记录。每条信源对应一次实际引用，保留问题、文章链接和观察日期，建议带标题、媒体和平台。不要提交仅含汇总次数的文章表。

在暂停页提交缺失文件，支持 XLSX、CSV、JSON，可一起提交或分次提交。以下 `TASK_REVISION` 应替换为当前页面显示的 revision，每次继续前读取最新值：

```bash
TASK_DIR='/绝对路径/当前任务目录'
TASK_REVISION=7
./scripts/frontmind continue --job-dir "$TASK_DIR" --revision "$TASK_REVISION" \
  --monitoring-answers '/绝对路径/本题完整答案.csv' \
  --source-workbook '/绝对路径/本题逐条信源.csv'
```

若只缺信源，仅传 `--source-workbook`。答案或信源没有可匹配日期时，随信源上传增加 `--source-period '当前页面显示的期次ID'`，明确绑定当前期次；不能用它改写其他问题或其他期次的数据。字段模板见 [examples/v16_4](examples/v16_4/README.md)。原有两份完整答案文件入口和更新后的 Pack 上传入口仍保留。

文章池按实际引用次数降序排列，同一页面链接去重；不足 20 篇就展示实际数量，不凑数。页面显示编号、标题、媒体、被引用次数、链接和选中状态。Top20 是引用频次排序，不是文章质量排名，也不是标题候选数量。

```bash
./scripts/frontmind article-pool --job-dir "$TASK_DIR"
./scripts/frontmind article-pool --job-dir "$TASK_DIR" --all
```

第一条打印 Top20，第二条打印完整文章池。完整 Markdown 保存在任务的 `research/article_pool/all_articles.md`，前 20 篇保存在 `top20.md`。

在原有例文确认页，须选择 1—2 篇构思参考，或明确不采用。可以选择完整池中第 20 名之后的编号。选择与原有文风方案可一次提交，例如：

```bash
./scripts/frontmind continue --job-dir "$TASK_DIR" --revision "$TASK_REVISION" \
  --pool-selection 1,2 --example-route A
```

`--pool-selection none` 表示不采用额外文章池参考；原有 A／B 文风选择仍独立保留。P01 的原有方案 A 继续采用金蝶主参考、ThinkPad辅助参考，文章池选择不覆盖它们。仅提交池选择会刷新同一确认页，随后按新的 revision 确认文风方案。

选中文章必须取得完整原文。取得失败会留在同一页，可以改选，也可按所选编号顺序补交完整 `.md`／`.txt` 原文，每篇使用一次 `--pool-example-file`：

```bash
./scripts/frontmind continue --job-dir "$TASK_DIR" --revision "$TASK_REVISION" \
  --pool-selection 1,2 \
  --pool-example-file '/绝对路径/第1篇完整原文.md' \
  --pool-example-file '/绝对路径/第2篇完整原文.md' \
  --example-route A
```

文章池只提供切入、选材和详略方面的构思参考，不提供企业事实，也不替代正文文风例文。v16 准备轮仍实际搜索并阅读全文两篇匹配当前场景的专项案例；池选择、专项研究和正文文风参考各自保留用途。

## 已确认定位的传递

新 P01／P02 的有效已确认问题定位会进入编辑准备和正式蓝图，使对象关系、差异化角度和介绍重点实际参与选材与构思。未确认或题目、品牌、Pattern 不匹配的定位不传入；P02 还须匹配当前选定三家及顺序。

定位是当前委托的补充，用户明确写作要求与当前三家选择优先。重新确认定位后，旧蓝图自动生成的定位字段不再覆盖新定位；明确的字数、排版和参考用途保留。正文作者仍接收干净材料、正式蓝图与约定文风例文。

## P02 对象选择

新P02默认先筛出本题相关综合企业实力明显强于主品牌的候选，再要求同题同期AI提及率高于主品牌，按平台等权提及率从高到低自动选两家；并列按名称稳定排序。主品牌先介绍。用户明确指定两家时以指定为准，常规自动选择不再暂停确认。首次不足两家自动补研，仍不足时才请求必要资料或调整标准。整体品牌定位的比较范围与定位确认继续保留。

新选择合同为 `frontmind-p02-auto-dual-strength/2`，后台记录比较理由、来源、期次、各平台分母和自动决定；实力采用定性资格判断，不计算虚假的加权总分。每答每主体最多计一次，平台等权。名单以 `comparison_targets` 保存，`peer_examples` 为空，贯穿定位、准备、蓝图、正文与编辑；写作上下文只传名称、顺序与正向重点。

用户已经明确指定两家时，入口直接用既有 `--competitor-selection` 提交其决定，不另问一次确认；`--confirm-competitors` 仍兼容，但新合同无需该参数。沿用指定名单并补齐材料，不强制其满足自动筛选标准。`--rerun-positioning-research` 可重跑本题选择。变更题目、期次或委托使旧选择失效；已完成稿先留存旧稿，再进行新的选择与写作。旧人工合同及冻结请求按原流程恢复，不自动替换名单。整体品牌定位流程保持原确认节点。 显式本题重研开启新执行标识，保留P0与核心定位。

```bash
./scripts/frontmind continue --job-dir "$TASK_DIR" --revision "$TASK_REVISION" \
  --competitor-selection '{"comparison_targets":["用户指定企业甲","用户指定企业乙"],"peer_examples":[]}'
```

程序使用本题本期的全部有效监控回答，按每答每机构一次、平台等权计算提及；不把提及率称作引用率。缺少逐机构正向推荐和引用标注时记录未知。窄范围选择更新保存为资料包的 `strategy/p02_selection.json`，不删除或重做 P0，也不覆盖原核心定位。

## 写作与标题

P01 可以把具体特点放进合理场景，写出直接便利、体验和吸引力。编辑删除空泛或重复总结，保留自然价值表达，不把文章压成资料摘要。不固定场景数或段落公式；事实、实际服务与效果判断有依据，不编造经历。

准备阶段按本题体裁阅读原件及两篇完整案例。素材直接介绍对象或事件，蓝图简短交代内容与主次。文章池只帮助构思，完整文风例文进入初稿、全文编辑和返工；编辑不再接收蓝图章节脚本。

默认按有效信息量展开，蓝图建议字数和例文长度只是参考。只有用户明确指定的硬性字数范围才校准。通过已有写作要求入口提交JSON中的 `body_character_range`，例如 `{"minimum":3000,"maximum":3600}`；预计字数字段 `estimated_length` 不自动升级为硬范围。已完成文章仍使用已有 `--manuscript-edits` 与 `--writing-requirements` 入口。

自然文风验读仅返回 `needs_revision/comments`，不做局部替换，也不回查知识库或修正事实。需要修改时以最近失败稿与阅读意见继续全文编辑，每次修订后再读完整稿；通过后正文原样用于标题、导出和续改。原稿与各轮实际结果保存。技术失败继续使用原有显式重试。

任务内 `reviews/article_process.html` 展示实际稿件、当前步骤和编辑结果，不调用GLM或其他模型生成过程摘要。额外可视化应用的接入说明见[适配说明](docs/visualization_v165_integration.md)。

新P0—P06统一使用 `frontmind-category-titles/4`：恰好10项，前五项 `style=formal`，后五项 `style=scenario`，每项含 `title`、`angle`、`style` 和 `usage_hint`。两组仍是同一篇文章的替换主标题，但每题只抓一个重心，整体应让读者看到不同入口。数字、渠道、技术、设计、人物和事件按实际内容选择，不固定五个栏目，不把局部段落拆成另一选题。

`usage_hint` 是1—2个建议投放位组成的数组，可选“文档标题、公众号B端、公众号C端、方案页、新闻稿”；只供后台选用。候选与最终标题表保留 `title_notes` 数组，无需说明时为 `[]`。

拟题前由 `shared/title_ammo.py` 整理最终正文与当前明确的 `title_ammo_extra`。每条素材保留原句、对象关系、输入来源和正文是否覆盖的标记；不会把孤立数字和机构拼成新的事件或背书，也不把写作字数、标题数量等指令提取为产品数字。正文未展开的补充素材由编辑按全文主线取舍，必要说明留在后台，不自动扩写正文。

正式组建议18—32个可见字符，场景组建议20—32个；完整品牌名称和用户硬性要求优先。`shared/title_quality.py` 提示相近换序、并列堆砌、机制套话和重复句式，编辑通读整组后判断，必要时整组重拟。提示不阻塞发布；不设数字覆盖配额、禁词清零或质量分数。

| 类型 | 前5项正式标题的写法 | 后5项场景与卖点的写法 |
|---|---|---|
| P0 品牌深度介绍 | 介绍本品牌与产品业务，十项均带当前品牌名 | 从正文中的用途、服务场景或特点进入品牌介绍 |
| P01 单主体推荐 | 保留一家主体的推荐任务 | 用具体场景或特点呈现同一主体的选择理由 |
| P02 多主体推荐 | 覆盖全文选定对象的推荐任务 | 从三家共同面对的场景或全文比较的特点切入 |
| P03 场景解决方案 | 保留场景问题和解决做法 | 从使用情境、流程或方案特点切入 |
| P04 事件新闻 | 保留事件、人物或实际进展的新闻主线 | 从事件涉及的使用场景或发布内容切入 |
| P05 点名对象对比 | 保留题目点名对象与比较关系 | 从正文实际比较的场景或差异切入 |
| P06 评价与选择 | 回应对象怎么样、好不好或值不值得选 | 从具体用途、体验或特点形成评价入口 |

v4的品牌策略继续为 `preserve_pattern_policy`：P0十项均包含当前品牌名；P01/P02默认不出现品牌或机构专名，用户明确标题要求优先；P03—P06沿用当前选题的对象命名，事件报道、点名对比和“怎么样”评价保留必要主体名字。P01可以用“这家机构”，P02始终覆盖正文实际名单；历史十一家稿只改标题时仍覆盖十一家。formal是正式标题组的标识，不要求新闻、对比或评价写成推荐文。推荐项可来自任一组，标题独立交付，不回填正文。

## 历史任务与显式修改

文章池与定位传递使用原有新任务标记；自然写作使用frontmind-natural-prose/16.5。旧合同保持原输入、策略和恢复方式，不补造文章池，不把旧正文重试升级为新流程。模型、网关和配置文件保留原值；新的全文返工轮次按实际阅读需要发生，不增加事实审计或过程摘要调用。

`frontmind-category-titles/1` 的10项旧策略、`frontmind-category-titles/2` 的P01/P02五加五策略、`frontmind-category-titles/3` 的P0—P06五加五策略及无标记的20项旧任务，普通续跑和重试继续使用原冻结请求。v3规则保留在 `writing_context_v14.py`；v4由独立的 `title_editorial_v168.py` 路由，不改旧请求。不会因安装本包自动改写旧标题或正文。

对已完成P0—P06显式执行 `continue --title-edits '/绝对路径/修改要求.txt'` 时，先留存原版本，再升级标题到 `frontmind-category-titles/4`，只重生成10个5＋5标题、标题编辑与交付文件。正文及其哈希、正文合同、定位、资料和例文保持原版本；不重跑准备、蓝图、初稿或全文编辑。旧P02十一家文章只改标题时仍覆盖原正文全部主体，不暗中删成三家。

历史v16.7五组标题继续作为旧合同案例保留，不当作v16.8生成结果。具体实际调用、阅读意见与交付版本见本版案例与验证记录。

将旧多主体文章改为三家，请新建 P02 委托并重新选定名单、准备材料、蓝图和正文；只改标题不会完成正文范围迁移。
