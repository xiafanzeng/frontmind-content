# Final v16 当前执行说明

新建 P01、P02 默认使用 `frontmind-natural-prose/16`，当前操作以 [README](../README.md)、[START_HERE](../START_HERE.md) 和 [v16说明](../FIX_v4.13.2_Final_v16.md) 为准。P0 和其他 Pattern 继续使用各自合同；历史任务与请求按冻结版本恢复，不自动升级。

当前正文链为：**独立编辑准备 → 正式蓝图 → DeepSeek 初稿 → E8 全文编辑 → XTY 最后文字编辑 → 独立标题 → 导出**。编辑准备属于新增的正式 XTY 动作 `article_editorial_preparation`；它先实际搜索、获取并完整阅读两篇符合当前企业场景与文章体裁的已发布案例，再结合企业原始材料完成编辑取舍。P01 使用单主体介绍案例，P02 使用多机构推荐案例；既有参考材料仍保持用户约定的用途。

准备轮向后提供自然事实段落和基于案例、编辑经验的蓝图建议，不输出正式章节、不设置事实缺口或审计流程。结果冻结到 `editorial/article_preparation.json`，企业事实来源与案例记录分开。蓝图轮只能使用当前委托、已准备内容和建议，不读取原始知识库；程序继承准备轮的素材及来源，XTY 蓝图轮才决定正式构思。

自然事实段落提供内容基础和方向，不限制原句、顺序或逐项覆盖。蓝图和作者可充分组织、润色、美化，首要目标是漂亮、自然、重点清楚的完整文章。E8 从全文阅读效果出发改善表达与衔接。`count_article` 提供实际正文长度，按当前委托范围校准，不代替编辑判断。

XTY 只读当前完整稿与写作要求，通过或提交可精确应用的句级微调；需要内容重组时由 DeepSeek 返工一次，随后 `article_polish` 再读返工全文。仍有主要问题时保留待修改，不自动增加付费循环。最终来源记录 DeepSeek 基稿与 XTY 局部编辑，标记实际合同；标题、Word、Markdown 和后续修改使用同一最后正文。成稿来源验证包含已冻结的编辑准备及其正式模型动作。

新 DeepSeek 请求默认 `high`，宿主模型、作者模型和网关读取现有 `config`。旧冻结请求按原配置恢复，旧 `max` 不被改写。仅修改蓝图组织时复用准备结果；新增原件或改变实际委托时重新准备。普通正文与标题精修不重新搜索，v16 新材料通过蓝图补料入口处理，不直接用 `--writing-materials` 注入作者。

使用已具备 `requirements.txt` 依赖的 Python，按 README 设置或保留 `FRONTMIND_PYTHON`；预检与案例命令使用同一解释器。实际案例入口为 `scripts/run_taixin_v16_case.py`，配置位于 `customer_inputs/taixin/v16/`。`prepare` 只在新目录准备输入；`blueprint` 也会新建任务，再完成编辑准备和正式蓝图；`all` 从新任务完整执行。已执行 `prepare` 的同一目录应使用 `resume` 推进到蓝图确认，再用 `write` 接受已生成的案例蓝图并执行正文链。`resume` 恢复已保存阶段，不重新建任务。API 失败沿用显式重试入口。案例的行业、名单、字数和版式由配置决定，不扩展为所有文章的通用要求。

入口助手只执行正式程序、传递真实输入和用户决定，不代写正文或修改模型结果。交付时阅读全文并逐页检查 Word，不能用动作成功、字数达标或来源记录替代语言质量判断。

下文保留基础接口及历史版本说明。各历史段落中的“当前”“默认”“本版”仅指其所标版本，不能覆盖本节 v16 流程或现有配置；仍适用的 P0、Pack、选题接口按各自合同执行。

## 历史 v4.13.1：P0品牌标题与Pack选题基础接口

用户选择“问题优化/article”后，只需确认已有Reference Pack，随后程序在 `awaiting_question_selection` 显示当前监控期次的问题清单。不要在创建Job之前强索问题ID、问题原文或两篇答案。把用户所选序号、ID或完整问题转为当前revision的 `continue --question-id 序号`；已知问题可直接传ID，仍保留Pack路由确认。选中问题后自动复用同题同一期两平台全文，保留全部原始观察，再进入原E1回答要点确认。禁止替用户选第一题。

P0完成只说明品牌文章可用，不表示问题库已建立。读取实际完成返回的 `next_step`，不要自行输出“现在只差问题ID和两篇答案”。已有问题库直接进入选题；没有目录时，使用 `reference-pack import-questions --pack PACK --monitoring-answers 原表.xlsx`，或在选题暂停通过同名参数导入。单表即可，不要求空的引用工作簿。缺引用明细明确记为未提供，不把截图当引用、不伪造研究完成。导入保留旧Pack，生成新版本并保留定位与P0。

当用户提交监控表，不得作为普通企业事实抽取。表内问题、完整回答、平台及监控日期是研究输入；日期以单元格为准，不能用导出文件名替代。已有数据不重复索取，只处理真正缺失或不匹配的数据。正文改标题可使用现有 `--title-edits`，不重跑初稿/E8/第三遍。

本版没有用户本地已修复的SDK源码；不要覆盖本地config、jobs或已工作的运行适配层。优先用 `scripts/upgrade_to_v4131.py --target 原程序目录` 检查，再加 `--apply` 合并；冲突会先停止，不猜测或回退本地修复。执行前暂停该目录的活动任务。具体命令见本版执行手册。
