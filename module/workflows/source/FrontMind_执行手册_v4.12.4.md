# FrontMind v4.12.4 执行手册

## 1. 本次修复的体裁偏差

用户指出的自动化与人工审计段落，把正文重点放在“两个方法分别检查什么”。准确并不等于完成品宣任务。新版第三遍要在既有事实中建立品牌认识，再让项目与专业动作支撑这个认识，而不是在说明段落后追加一句空泛赞美。本文只说明编辑方法，不提供由入口会话代写的一航稿。

第一遍组织完整业务内容；第二遍处理事实、逻辑、遗漏与重复；第三遍读两篇真实全文后实际编辑成稿。第三遍不只替换段首，不以更多术语、长句和形容词模拟深度。业务主题和事实受到保护，但模型先前写出的句法、详略和普通小标题不是不能修改的业务决定。

## 3. 实际模块

`shared/brand_stage.py` 组装新P0的五个实际阶段Prompt；`shared/brand_references.py`只在第三遍取得并冻结两篇全文；`shared/writing_context.py`按合同分支；`shared/host_tools.py`阻止宿主经文件或已知例文URL提前读取模板；`shared/model_runtime.py`保持固定模型与输入指纹；`shared/managed_runtime.py`保留原生托管事件适配。

来源文本与编辑说明分开保存。正文修改属于DeepSeek；Managed Agent只验读候选与事实。断流、错误模型、缺少正文、伪造修改说明、不存在的对照引文、不合格终审，均不会被当作正式交付。格式检查不是语义评分，也不是自动文采证明。

## 4. 一航源稿修订入口

```bash
./scripts/frontmind preflight
./scripts/frontmind rewrite-p0 --live
```

可指定新来源和目录：

```bash
./scripts/frontmind rewrite-p0 --live --source /absolute/source.docx   --brand '完整品牌名' --requirements-file /absolute/requirements.md   --run-dir /absolute/new-job
```

来源只支持普通MD/TXT/DOCX。首次调用记录来源哈希与真实委托，之后输入变化不覆盖既有任务。`--live`授权本次实际付费模型执行；没有伪造离线成稿开关，也不自动回退其他模型。该入口是限定源稿重写，区别于需要企业材料、定位和确认的新Reference Pack流程。

包内一航来源由上传v4.12.2 Word机械提取，标识位于customer_inputs/yihang/source_identity.json。旧稿内容仍是待核对的修订依据，不因打包而升级为一手事实。严格保留历史气体系统项目、51个功能用例与42个性能用例的归属，不虚构客户缺陷、收益、推荐引语和当前资质。

成功输出正文MD/HTML/DOCX及独立20标题。文章主标题不写入正文Word。原始稿、E8、第三遍、终审、拟题与标题编辑结果均保存；只做确定性排版。导出后应逐页检查文档，不能把文件存在当作版式验收。

## 5. 失败与复用

```bash
./scripts/frontmind rewrite-p0 --live --retry-current-action
```

普通运行复用经重新验证的成功结果，但不重发失败付费请求。DNS失败标明未发送；未知POST结果保持待核对，避免重复创建资源。联网后显式重试恢复原动作，仍不绕过事实、结果和来源校验。终审要求大改业务内容时返回具体问题，不伪造用户确认。

完整性校验只能拒绝明显不完整的源文，不能证明网页内容全部正确。源站结构变化、权限、账户或实际协议不匹配仍可能需要联调，本版不隐瞒这些限制。
