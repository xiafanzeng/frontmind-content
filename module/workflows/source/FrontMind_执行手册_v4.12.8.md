# FrontMind v4.12.8 执行手册

## 本版用在哪里

主要替换P0的第三遍润色。E8保留事实和篇章编辑职责，只补充几类会污染后续表达的内容处理。第一遍不变，不新增第四遍，不修改两篇原始例文，不加入评分Agent或词黑名单。

## 启用与旧任务

在新目录解压完整包，先执行 `./scripts/frontmind preflight`，再运行 `./scripts/frontmind`。新建P0的metadata.p0_style_contract应为frontmind-p0-style/4.12.8。已有Reference Pack正常复用；业务确认按原流程执行。

旧Job保留旧版本，覆盖程序文件不能使已完成稿自动变成新稿。不要手动改旧Job合同或删除旧模型记录。新规则需新P0任务；保留原稿用于全文对照，不把对照稿单独冒充原始事实资料。

## 正常写作

1. 选材：保留原件支持的业务事实、必要状态和范围。已完成、又不再约束本篇的核验经过不持续累积进material_adjustments。
2. 初稿：按已确认任务正常成文，原角色不变。
3. E8：完成事实、信息关系和段落组织的编辑，处理强断言及重复条件。不读例文，不运行完整第三遍Skill。
4. 第三遍：一次既有p0_style调用，由DeepSeek读E8全文、本篇任务和事实条件、两篇原始例文，加载本地P0编辑Skill后输出整篇Markdown正文。
5. 验读、20标题、导出：沿用既有分工。验读通过后逐字保留第三遍候选，不由宿主换写正文。

上述是原有阶段说明，不是新增轮次。没有自动‘再humanize一遍’。

## 第三遍的具体改法

当段落在介绍资料证明什么、官网如何展示、作者怎样核验或品牌怎样说话时，先确定它实际要介绍的业务，再重写段落。只重复评价前文的句子可以删除，不补‘理念’‘优势’等另一句评价。

但归因和否定本身不禁止。宣传图片未核实不能变成设施现状，计划不能变成已开展，有限范围不能变成普遍承诺。效果差异和项目限制放在相关内容附近，不能全压成‘以实际为准’。正文可以解释有用的业务关系，无须句句短、处处删减。

## 模型及输入核对

实际代码入口为 `shared/prose_only.py:role` 与 `shared/model_runtime.py:_initial_messages`。新版本标记分别是frontmind_brand_stage/4.12.8与frontmind_prose_only/4.12.8；第三遍系统内容应含资源文件SKILL.md的正文。前两遍没有完整Skill，终审不重新读例文。

查看实际保存的请求时不要对外复制模型配置文件或凭据。Skill缺失或manifest不匹配会停止并报资源错误，不启用旧提示。自改Skill须同步manifest及测试；不要把这种本地变更声称为官方发行或已完成内容验证。

## 失败与返工

终审返回incomplete时，保留具体问题说明及冻结候选。纯表达与篇章问题用原有style返工；事实/内容需要回改E8则选edit。不能同时请求返工与retry-current-action；不自动循环调用模型。

正常P0：
```bash
./scripts/frontmind continue --job-dir /absolute/path/jobs/p0 --revision N --p0-rework style
```
N为当前revision，需回E8时将style改为edit。源稿限定重写使用同一run-dir以及 `rewrite-p0 --live --rework style` 或edit，并保持source、brand、requirements一致。新事实或业务变化使用原蓝图/补料入口。

## 怎样验证写作效果

保留同一已确认材料与任务的旧稿、新稿，并通读全文。重点看句段是否转成实际业务介绍，是否只换了‘这些事实’的外壳，是否新增承诺或删去必要条件。另用不在Skill示例里的品牌段落检查，避免只修两个短语。

acceptance_fixtures/p0_prose_editor_v4128中有合成对照案例和保护条件，不是模型实测成绩。程序回归和ZIP检查不能替代真实文章验读。本次升级不自动消耗API配额，没有已经通过真实生成的台心新稿。
