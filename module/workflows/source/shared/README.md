## 本次修订的表达与执行配置

定位最终页只呈现“核心定位”与“与已确认竞品的比较”，随后进入原有确认操作。核心按“适合谁 → 品牌怎样满足需求 → 用户得到什么”写成两三句自然表达，默认约100—180字，无字数门槛或机械截断；不列执行清单、目标企业缺点或例行免责尾句。比较说明按确认对象组织已知价值、决定性区别和适配需求；确有依据且影响选择的费用、等待时间、交付边界按需说明，不要求每组列短板。有依据且有意义时分档并解释相邻顺序，否则并列比较。具名对象可分组，但个体事实不能扩大到整类；同类举例不参与胜负判断。

后台研究用于决定哪些陈述成立；公开核心、竞品比较和文章不复述资料完整度、来源收集过程、信息缺口或内部角色规则。缺少某项比较依据时省略该项优劣或排名，不把信息缺口当对手短板。来源与必要限制仍保留在Pack和内部上下文，资料处理使用已有内部字段。用户明确询问价格、风险或缺点的文章仍直接回答。

综合动作按“已注册的完整文本原料与选定研究 → 最终写作任务”的顺序组织输入，不截断或改写事实。正文中的任意文件链接不会自动成为新的读取来源；非文本资料继续通过已有材料入口读取。P01/P02 明列现有 JSON 字段名，后台备注写入 material_adjustments。

最终页不展示独立证明材料、研究限制、经营建议或研究附件链接。原始资料、来源及历史必要条件仍在 Pack 内供写作使用；新结论的必要条件直接写在对应核心或比较句中。公开定位 Markdown 与确认页共用渲染，核心 JSON 是最终结论唯一依据。`user_choice_value` 仅保留摘要兼容，`advantage_explanation` 保存完整可读的竞争比较；不新增必填字段、Critic 或用户暂停。

P01/P02 在需求、对象和事实相同时沿用已确认比较理由及有依据的先后；条件改变时解释调整理由。蓝图与作者使用本题已确认顺序，不机械复制整体名次，也不另行把品牌前移。本次生产与实测使用当前任务冻结的供应商、模型和推理档位，由宿主的 Agent/会话执行配置决定，不在工作流或行业 Prompt 中固定供应商或模型；异常不静默换模型或降档。旧 `glm-5.3 / high / standard` 的验收观察仅供历史对照，不能代表当前配置已经验收。通用 Workflow 的内部 Provider 协议保持不变。

## 轻量定位接口

定位正常运行两个内部 Provider 动作，并有竞品确认、最终定位确认两个业务暂停：

```text
positioning_market_research：研究真实选择与竞争关系，提供候选对象
→ awaiting_competitor_selection：用户确认比较对象与同类举例
→ positioning_value_synthesis：在确认范围内综合选择理由与表达
→ awaiting_core_positioning_confirmation：用户确认最终定位
```

研究以企业原始材料、当前要求和可用公开信息为依据，发现强替代者、同类品牌和其他解决方式；区分企业自述、查得的信息和推断。研究先提供候选，不决定品牌位置，不把所有查到的品牌自动当成定位对手。候选按类型组织，显示名称、对象类型、所属类别、自然研究说明及相关来源。控制器生成选择用标识；普通用户可以通过对话增删对象、补充名称或类别，无需填写 JSON。

## 比较范围与角色

竞品页允许用户将每个候选设为“比较对象”“同类举例”或“不纳入本次定位”，并在同页展示本次范围的自然语言预览。用户确认的是要和谁区分，不是预定胜者；无须再确认独立的比较模式。

| 关系或角色 | 定位含义 |
|---|---|
| 类型间比较 | 相对于已选的其他类型，说明目标品牌所属类型为何适合这群用户；不要求证明同类独有。 |
| 同类型比较 | 相对于选定同类品牌，说明品牌层面的实际差异；共有类型能力不能冒充品牌独有。 |
| 混合比较 | 分别解释类型价值和同类型品牌差异，不把两个层次混成一个胜负结论。 |
| 同类举例（peer examples） | 只用于说明所属类别，不参与优劣论证；不得因同档示例也有类似能力而否定类型价值。 |
| 不纳入本次定位 | 留在研究资料中，不自动进入本次核心论证。 |

`comparison_scope` 由控制器保存实际比较对象、同类举例和用户确认的范围说明，并写入最终 `core_positioning.json`；综合模型不能自行新增对手、重分角色或改写范围。范围随核心对象导出，不增加旧 Pack 必须具备的独立文件。旧 Pack 没有该字段时仍可读，不能根据旧正文或示例自动推定。

候选的 `relation_to_brand` 用 `same_type/different_type/unknown` 表达本题的类别关系，与用户选择的角色分开。新研究明确提供该关系，Schema 为旧数据保留可选兼容；缺字段时只能将完全相同的类别识别为同类，不能因文字不同就认定异类。范围内补研全文直接保留，新增品牌事实不会因同段提及同类举例而被删除；可选 `brand_research_markdown` 只承载品牌相关研究，不成为必填门槛。

分档只有在有助于本轮需求时使用，也可以并列比较。第一档由确认范围内的需求与比较支持；目标品牌在档内首先展示属于呈现顺序，不表示优于同档其他品牌。“第一档第一位”不能扩写为全市场第一或同类独占。高代价事件、便利、成本、专项深度、持续服务的重要性由本轮需求决定，没有分档不表示研究失败。生产 Prompt、流程及默认示例不预置特定行业答案。

新增对象资料不足时复用市场研究动作补查，不增加 Critic 或额外审批。对象重名或无法识别时，在当前竞品页请求用户指明。无法支持某项优势时如实收窄，不因用户选了比较范围就宣布品牌获胜。

## 综合与展示

综合阶段接收目标品牌材料、已确认比较范围和相关研究。优先提供已选对象的研究说明与原文入口，同类示例只提供举例所需信息，未选对象不再作为默认对手灌入上下文。

核心问题是：面对用户确认的这些选择，品牌最值得哪类用户选择，理由是什么？可以是单项专长、交付方式、适用条件或几项能力共同带来的价值；不预定优势数量、组合方式、首位或独占地位。几项业务只有共同改变同一个用户选择才构成组合价值。仅作同类举例的品牌不参与胜负判断；若实际比较对象同样满足需求且代价不更高，则应收窄相对优势，不以材料篇幅制造领先。

研究 Provider 返回 `research_markdown`、`sources`、`brand_category` 和 `competitor_candidates`。`brand_category` 表示目标品牌本轮的可比类别；候选的 `name`、`category`、`kind`、`research_notes`、`source_urls`、`suggested_role` 分别记录名称、类别、对象类型、自然研究说明、来源和建议角色。`kind` 为 `brand/category/alternative`，`suggested_role` 为 `comparison_target/peer_example/excluded`；建议不代表用户确认。

综合 Provider 返回 `user_choice_value`、`core_positioning_paragraph`、`advantage_explanation`；`applicability_notes` 是可选说明。候选标识、品牌名称、版本、文件路径和确认范围由控制器维护。Schema 只验证结构，不验证行业关键词、优势数量、排名或逐字因果链。

最终页按“短结论 → 优势说明 → 完整定位段落 → 比较依据、证明与适用条件 → 确认选项”展示。核心正文默认约150—250字，以完整自然表达为准，不设字数拦截；集中说明适合谁、有价值的不同和用户收益。影响句子真实性的条件留在原句，证明细节和详细短板另列。没有的排名、投入和取舍不显示空栏，未确认的经营退出不能自动成为决定。

`core_positioning.json` 是最终定位的唯一依据。旧完整结构和已确认 Pack 保持可读，旧方向文件仅从最终结果投影，不反向推导，也不补造缺失的范围、排名、后果链、投入或经营放弃。新结果不运行独立润色、方向生成或 Critic。无法判断时在已有业务页说明目前能判断什么、还缺什么，不因没有排名或不是唯一领先新增暂停。

## 操作与刷新

所有操作沿用当前 `revision`，空 `continue` 只重显页面，内部 Provider 不能代替用户确认。

| 入口 | 行为 |
|---|---|
| `--competitor-selection` | 接收选择用 JSON 或其文件路径，编辑候选角色、名单与范围；对话运行者根据用户自然表达提交，不要求用户写 JSON。 |
| `--confirm-competitors` | 明确确认当前比较范围，之后才进入综合；不能代确认最终定位。 |
| `--return-to-competitors` | 返回竞品页，更换对象并使旧定位确认失效；重新确认范围后再生成。 |
| `--core-positioning-edits` | 保留已确认范围，仅重新综合表达；需要换对象时使用返回竞品页入口。 |
| `--positioning-supplement` | 保留已确认范围，补研新增事实后再综合，不自动扩大对手集合；尚未确认范围时留在竞品页。 |
| `--explore-positioning-alternatives` / `--rerun-positioning-research` | 从原始材料与最新要求重新研究，旧选择作为可编辑预选，回竞品页再次确认。 |

选择参数的顶层为 `comparison_targets` 和 `peer_examples` 两个数组，条目可以引用候选编号、名称或带 `name/category/kind` 的新对象。两组中都未选择的候选表示不纳入；同一对象不能兼作对手和举例。运行者依据对话整理这些技术字段，不能把角色判断交还给用户填写 JSON。确认前至少需明确一个其他品牌、类别或解决方式作为比较对象，这是本次选择范围的定义，不是调研数量门槛。

旧定位与 P0 可以作为历史内容参照，不是新事实来源。旧未完成动作通过现有研究刷新入口进入新流程，不能将旧中间对象与新流程混用。已确认 Pack 和原发布包不覆盖；确认新修订后导出新 Pack 版本。

## 下游与验收

P0 接收已确认正文、优势解释、比较范围和相关材料，不强制高代价开篇，也不把范围内结论扩写为全市场排名。P01/P02 相同条件沿用已确认比较依据，条件变化时解释调整；需要不同对象时在已有问题定位页说明，不静默改写品牌整体范围。作者按任务使用相关内容及自然语言范围说明，不反复灌入整个历史定位对象。

离线测试验证结构、两次正常 Provider 动作、两个定位业务暂停、范围传递和旧 Pack 兼容。真实 glm-5.3 输出另行观察范围语义、事实变化和跨行业表现；离线通过不证明定位质量达标，三轮开发迭代也不变成每次生产的三稿生成。报告分别记录实际完成与未验证部分，不将示意段落或人工改写冒充模型实测。不新增语义评分、来源数量门槛或独立审批。

来源沿用 `{title, url, accessed_at, use}`；未知 URL/日期可为 null。控制器写入 `schema_version`、`artifact_type`、`brand`，并维护既有研究文件路径。Schema 兼容旧完整对象与新轻量对象；两者不要求互相补全。

正常新 Provider 不必阅读或返回完整历史 Schema。旧方向的轻量投影只含最终正文、选择价值、优势解释及兼容元信息，旧字段有真实值才保留。Pack 容器成员名称和最终确认状态保持不变；`awaiting_competitor_selection` 是新增的定位业务暂停。
