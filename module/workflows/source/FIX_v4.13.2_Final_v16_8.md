# FrontMind Final v16.8：不同阅读入口的5＋5标题

本版以完整v16.7为基线，仅更新标题生成与编辑。P0—P06仍是前5个正式标题、后5个场景标题；正文、蓝图、例文、文章池、定位、竞品名单及模型路由继续原配置，DeepSeek保持high。新ZIP为 `FrontMind_Content_Workflow_v4.13.2_Final_v16_8_Diverse_Titles.zip`。

## 修改判断

旧标题主要从正文高频词取材，十项容易成为同一句话的换序，长流程、名词并列和内部机制词也一起被带进标题。本版先整理可以使用的完整素材，再为整组安排不同阅读入口，由标题编辑连读十项并直接修好表达；必要时整组重拟。

附件提出的不同入口、素材摘要、长度、并列和僵硬动词检查已经吸收。没有采用固定数字或专名覆盖数量、禁词清零、评分及确定性发布闸门。正式18—32、场景20—32个可见字符只是手机阅读建议，用户硬性要求和完整对象名称优先；内容稀疏时不补造卖点。

## 新链路与结构

最终正文＋明确补充素材 → 原句素材索引 → 按当前体裁拟定5＋5 → 编辑完整十项 → 标题与原正文一起导出。

`shared/title_ammo.py` 保留素材原句、对象关系、origin与body_covered。输入只取最终正文与当前明确的 `title_ammo_extra`，不把写作字数、候选数量或Prompt指令当产品数字。补充素材支持文字或 `{text, source}` 对象；提取不等于独立核验。正文尚未展开的内容由编辑按全文主线取舍，后台保留说明，不自动扩写正文。

`shared/title_quality.py` 给编辑具体线索，涉及过长、开头三项并列、内部机制套话、相近换序、精确angle重复和反复“从……到……／能……能……”。程序不据此判定通过或失败。P01/P02默认不出现品牌或机构专名，不产生与这个规则冲突的专名配额；长品牌名不因通常长度建议被强行缩写。

新合同为 `frontmind-category-titles/4`。每项含title、angle、style及usage_hint，usage_hint是1—2个建议投放位组成的数组，取值为“文档标题、公众号B端、公众号C端、方案页、新闻稿”。候选、标题编辑与最终标题表保留后台title_notes数组，无需说明时为[]。它们不进入标题正文，也不回填文章。

品牌与体裁规则延续：P0十项均含品牌；P01/P02默认不含品牌或机构专名，当前明确要求优先；P03—P06保留题目必要对象名称。formal完成对应品牌介绍、推荐、方案、新闻、对比或评价任务，scenario从同一篇文章的使用画面或选择理由进入。

## 使用与兼容

新任务默认v4。v1、v2、v3及无标记旧任务仍按原冻结请求、数量和结果恢复。v3提示保留在 `shared/writing_context_v14.py`；v4放在独立的 `shared/title_editorial_v168.py`，旧请求不会被新措辞覆盖。

已完成任务只有明确使用 `continue --title-edits` 时，才留存旧标题并升级到v4，重新拟题、编辑与导出；准备、蓝图、正文及其哈希不变。需要补充标题素材，可在标题修改文件中明确给出JSON块，例如：

```json
{"title_ammo_extra":[{"text":"当前产品或事件的完整素材句", "source":"当前原件位置"}]}
```

普通标题修改不重新搜索。补充素材不自动变成新的正文内容或事实证明。不要为满足标题数量而虚构事件、排名、使用经历或效果保证。
