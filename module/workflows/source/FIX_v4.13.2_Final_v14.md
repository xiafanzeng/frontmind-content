# Final v14 通用写作流程

新建任务默认采用 `editorial-mission-v2`。选材、蓝图、成稿和编辑共同使用新版规则，不需要临时改稿指令激活。文章体裁、介绍层次和篇幅来自当前委托，Pattern 负责内容关系。

## 文章任务与选材

P0保留品牌深度特写、固定例文和第三遍文风编辑。P01围绕具体需求介绍一个对象的业务、特点与服务；P02按确认的主体关系、推荐重点和顺序介绍多个对象。P03—P06继续完成各自的解释、新闻、比较与评价任务。人物、参数和技术机制只在当前任务需要时展开。蓝图的介绍层次明确区分对象整体、具体业务及专业过程；P01/P02默认采用对象介绍，主要篇幅给主体业务与服务，母体及行业背景简述。E8先按这一层次安排主次再编辑，不因基稿已有某节就照单保留。

新P01任务使用`p01_writing_v2.py`的独立简短写作入口，以有内容的推荐主线组织文章，数量与目录由内容决定。当前内部版本`single_subject_writing_contract=frontmind-single-subject/3`以article_brief决定体裁；介绍型新闻品宣直接写对象业务、特点、具体做法与服务，需求和合理场景用于引出对象，不转成读者选择、核验、咨询指导或作者宣传边界说明。蓝图保留原始材料的完整对象描述与信息组，不沿用资料目录、照片呈现说明和咨询话术。五阶段角色与蓝图工具说明整体替换旧使命，不叠加旧CORE和逐段压缩要求。XTY只审文字与阅读效果，不做事实、来源或资料缺口判断；短稿可以重新组织全文，测字只提供数字。标题不变；P01旧`/1`、`/2`、P0、P02及其他Pattern保留原路。

机构或产品介绍直接展开主体及其代表性业务，不逐项解释项目表，不转成读者如何选择、咨询或接受服务的步骤。此内容分配只用于介绍与推荐任务；P03的问题解释、P04的事件报道及其他明确任务，仍按当前委托展开所需的方法、过程、事件与判断。系统提示、蓝图字段与实际工具schema采用同一作用范围。

蓝图按主题和材料实际内容分配详略。`materials`只作页面概述，`writing_material_markdown`独立保存作者所需的全部选用内容，按阅读重点保留业务特点、普通解释、代表细节与服务情境。相关信息成组保留，避免压成密集的项目名称清单。资料中的使用提醒与作者安排留在后台字段。

选用素材直接记录本篇可写的对象与事实内容；来源评价、照片拍摄说明、资料缺失、不得推断等提醒及作者安排归`material_adjustments`，不进入正文素材。真实时间、范围和阶段等有助理解主体的条件，随对应内容保留。

`opening`说明怎样自然进入主题，`sections.task`安排具体内容和介绍顺序，各节篇幅合计对应当前目标。材料丰富的部分充分展开，材料简略的部分简述，结尾在内容介绍完成处结束。系统Prompt、蓝图字段说明与实际工具schema保持一致。

介绍型推荐优先读取机构、产品、业务、项目及空间服务材料，包括原始演示文稿和表格。已有直接材料时，不用咨询问答或旧AI回答替代选材。原始来源完整保留，AI回答可按需读取但不要求全文阅读，也不充当文风样本。真正的文风例文仍完整提供，并延续到成稿、E8、XTY和必要返工；P0保持原有例文使用时点。

## 成稿和文字编辑

正文链保持：DeepSeek成稿 → E8编辑 →（仅P0第三遍）→ XTY文字意见 → 必要时DeepSeek返工一次 → 标题与导出。

每个阶段只接收一份当前有效委托和篇幅目标，不另设中间写作预算。编辑时先读当前完整基稿，再读所需素材和例文；返工同时接收一次文字意见。素材和可调整构思以`reference_data`标识为参考数据，当前委托以`current_commission`独立放在输入末尾。素材中夹带的旧写作安排不覆盖委托，正式题目交代选题背景，全文重点与介绍层次由当前`article_brief`决定。正常编辑保留已成立的叙述和展开程度，修改影响阅读的部分，必要时重组段落，同类问题一并处理，提交完整修订稿。

程序统一统计正文可见字符，含小标题、标点、数字和英文，排除主标题、候选标题、空白及Markdown标记。范围内的基稿提示保持展开程度，低于范围才提示相关内容仍需展开；明确上限不转成补足任务。

新问题文章任务内部冻结`writer_count_contract`。其DeepSeek初稿、E8和必要返工在同一动作内可调用只读`count_article`，将拟提交的完整Markdown交给程序，获得同一口径的实际字符数，再按当前委托完成正文。工具不读写文件、不查资料、不评分、不设置数字通过条件；最终仍提交原有完整正文JSON。P0和标题流程不变，旧任务及没有专用测字标记的历史请求继续直出。工具会话保留DeepSeek原始推理字段及调用记录，中断后从完整原始测字回合恢复，不重写已完成的候选。

XTY只提出必要的文字编辑意见，兼顾导语、结构、详略、衔接、重复和篇幅，指出应保留或展开的内容；不核查事实、不回读来源、不补料、不改写正文。没有意见直接采用当前稿，有意见只调用一次DeepSeek返工，之后不再审正文。

已确认的主体、推荐关系与分档是持续写作要求，XTY不重新讨论其合理性，也不要求作者追加排序辩解或选材说明。编辑意见服务当前委托，不撤销其篇幅、体裁或推荐关系。DeepSeek保留未受影响的具体内容，删掉重复或偏题部分后，在同一次编辑中展开相关但未写充分的内容，完成文字质量与篇幅要求，不把整稿改成摘要。

DeepSeek保留`deepseek-v4-pro`、thinking enabled、`reasoning_effort=max`及65536输出额度；其他模型、网关、凭据和恢复配置保持原安排。最终正文单独记录真实DeepSeek来源，标题、Word及后续改稿都读取实际交付稿。Word保留原Markdown段落与加粗结构。

问题文章的标题作者与标题编辑共同保留全文任务：P01为单主体推荐，P02为多主体推荐；同组候选包含明确回应推荐问题的题式，并以正文真实推荐重点形成不同入口，不统一降为机构概览，也不把篇幅安排或章节说明写成主标题。其他Pattern保留各自任务，P0沿用原标题路线。已完成文章可通过既有`continue --title-edits`仅重新生成与编辑标题，冻结正文，不重跑正文链。

## 使用、恢复及验证案例

运行`./scripts/frontmind`进入原业务入口，`./scripts/frontmind preflight`检查运行环境。新任务自动使用v14；历史任务按已冻结的版本恢复。旧版分派、读取要求、原始输出与调用记录保留，中断恢复不会切换提示或重复完成的返工。

`customer_inputs/taixin/v14/`保存原始资料、已确认题目定位、例文用途和任务配置。P01约3000字，只介绍台心；P02约4330字，三档、11家及原顺序。两篇均为自然新闻品宣推荐，不介绍医生。P02档名独立加粗，机构名段首行内加粗。这些属于案例配置，不是跨行业模板。案例的`material_paths`明确本次采用的原始附件与背景、环境、接待资料；存档FAQ及咨询式网页文案保持原件，但不输入本次正文选材。通用入口不按医院名称或文件名过滤资料。

```bash
python scripts/run_taixin_v14_case.py --pattern P01 --job-dir jobs/taixin-p01-v14 --stage all
python scripts/run_taixin_v14_case.py --pattern P02 --job-dir jobs/taixin-p02-v14 --stage all
```

案例入口使用新的空任务，从原始资料重新选材、生成蓝图并实际调用模型；不导入旧正文、旧蓝图或历次改稿意见。`prepare`仅准备输入，`blueprint`生成蓝图，`write`接着完成成稿链。题目和业务选择沿用已确认配置。

开发验证读取实际全文判断成文效果，发现共性问题则修改正式输入并从新任务再跑；不手工改写生产终稿。程序验证覆盖实际请求、默认版本、旧版兼容、参考用途、持续要求、一次返工、中断恢复、真实终稿续改和导出。
