# Final v16.7：P0—P06统一5＋5标题

本版将原来只用于P01/P02的5＋5标题扩展到P0—P06。新任务使用 `frontmind-category-titles/3`，每篇独立交付10个可替换的主标题：前5个 `style=formal` 为正式标题组，后5个 `style=scenario` 为场景卖点组，每项含 `title`、`angle`、`style`。正文写作、文章池、例文、定位传递和P02自动选两家沿用现有流程。

## 各体裁的标题任务

| 类型 | 前5项formal | 后5项scenario |
|---|---|---|
| P0品牌深度介绍 | 正式介绍本品牌及产品业务 | 以正文中的用途、场景或特点切入品牌介绍 |
| P01单主体推荐 | 保留一家主体的推荐任务 | 用具体场景或特点呈现同一主体的选择理由 |
| P02多主体推荐 | 保留全文选定对象的推荐任务 | 以共同场景或全文比较的特点切入 |
| P03场景解决方案 | 保留场景问题和解决做法 | 以使用情境、流程或方案特点切入 |
| P04事件新闻 | 保留事件、人物或实际进展 | 以事件涉及的场景或发布内容切入 |
| P05点名对象对比 | 保留点名对象与比较关系 | 以正文实际比较的场景或差异切入 |
| P06评价与选择 | 回应怎么样、好不好或值不值得选 | 以具体用途、体验或特点形成评价入口 |

formal是组别标识，不将所有文章改成推荐文。两组均对应同一篇完整正文，场景组不要求五个不同人群或卖点；不把局部章节改成另一篇文章的题目。P02覆盖正文实际名单，历史十一家稿只改标题时仍覆盖十一家。

v3品牌策略为 `preserve_pattern_policy`：P0十项均包含当前品牌名；P01/P02默认不带品牌，用户明确标题要求优先；P03—P06沿用当前选题的对象命名，特别是事件报道、点名对比和“怎么样”评价保留必要主体名字。推荐项可来自任一组，标题独立交付，不回填正文。

## 历史恢复与只改标题

`frontmind-category-titles/1`、`frontmind-category-titles/2` 及无标记20项旧任务，普通续跑和重试继续使用原冻结请求。安装新包不自动改写旧正文、标题或生成记录。

对已完成P0—P06明确使用 `continue --title-edits 修改要求文件` 时，先留存旧版本，再升级标题到v3，基于当前完整终稿重生成10个标题并完成标题编辑与导出。正文及其哈希、正文合同、定位、资料与例文保持原版本，不重跑准备、蓝图、初稿或全文编辑。P0专用正文链不因标题升级而改变。
