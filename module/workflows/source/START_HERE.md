# 从当前客户开始：v16.8

资料包创建会把逐文件接收结果保存到 `inputs/material_intake_report.json`。如有附件被拒收，任务报告文件名与原因，并停止进入研究阶段。接收成功后，Agent 仍须提取并读取原件；图片中的文字另行识别。 OCR 回执给出正文编号与字符数，Agent 读取该正文后逐图归纳；同页背景图和主要图片分别判断。

失败或用户停止后，使用原 Job 的 `continue --job-dir DIR --revision N --retry-current-action` 恢复当前内部动作；N 取本次页面显示的原始 revision。执行器取得原 Job 独占锁后，复用已保存的请求和检查点。停止留下的 `pending_action` 即使尚无错误回执，也可以显式恢复；已经到达人工确认页时，提交该页的原生确认操作。

先读[README](README.md)，执行 `./scripts/frontmind preflight`。输入本轮品牌、原始资料和正式问题，使用 `article` 或独立 `p0` 入口；历史客户案例不是新任务默认输入。

企业资料可上传 PPTX。`extract_document` 按播放顺序提取文字、表格、备注并登记每页图片；用 `read_material` 读取提取结果，图片中的相关文字用 `ocr` 识别。没有原生文字的页通过 `pages_requiring_ocr` 指出。

新P01至P06采用frontmind-natural-prose/16.5：编辑准备 → 正向内容蓝图 → DeepSeek初稿 → 全文编辑 → 自然文风验读 → 标题与导出。需要修改时编辑最近完整候选，再读全文；允许口语、有限重复和不完全工整的稿件感。P0专用正文链与历史正文合同保持原流程。

P01只介绍一家；P02按综合企业实力明显更强＋本题同期AI声量更高自动选择两家竞品，主品牌在前，不再例行确认。用户明确指定名单时直接采用；资料不足先补研。P03讲场景解决方案，P04报道事件，P05比较题目点名对象，P06直接回应“怎么样、好不好、值不值得选”。P03至P06不增加逐题定位确认。

新P0—P06统一使用frontmind-category-titles/4，各10个标题：前5个style=formal为正式标题组，后5个style=scenario为场景卖点组。formal按本篇体裁写正式品牌介绍、推荐、解决方案、新闻、对比或评价；后组用场景或卖点切入同一篇文章；每题抓一个具体重心，整组提供不同阅读入口，避免同义换序。P0十项均带当前品牌名；P01/P02默认不出现品牌或机构专名，用户明确标题要求优先；P03—P06沿用当前选题的对象命名，新闻、点名对比和“怎么样”评价保留必要主体名字。每项含title、angle、style及1—2个投放建议组成的usage_hint数组，候选与终稿保留后台title_notes。素材来自最终正文和明确title_ammo_extra，原句、来源及正文覆盖标记一起提供。编辑通读整组，可以重拟；长度、重复句式与机制套话提示只帮助编辑，不设数字配额或发布门控。标题独立交付，不回填正文。v1—v3及无标记20项历史任务照原冻结合同恢复；对已完成稿明确使用--title-edits才升级标题到v4，正文与正文合同保持原样。

先复用Pack同题同一期的完整答案与逐条信源。缺少两个不同AI平台答案或引用信源时，停在原输入页补齐，通过 `--monitoring-answers`、`--source-workbook` 上传XLSX/CSV/JSON；无法匹配日期时用 `--source-period` 明确期次。XLSX 可使用平台工作表及“答案1／答案2”双层表头，保留各次回答和原始行号；引用编号和截图仍须对应独立信源明细。字段和命令见[输入模板](examples/v16_4/README.md)。

用 `article-pool --job-dir 任务目录` 查看Top20，加 `--all` 查看完整池。在原例文页用 `--pool-selection 1,2` 选择构思参考或 `none`；原文取得失败可用 `--pool-example-file` 补交。文章池只影响构思，P01金蝶与ThinkPad文风参考、两篇专项案例研究及已确认定位传递继续保留。

默认字数按有效信息量决定，建议篇幅只是参考。用户明确硬性范围才通过已有写作要求JSON中的body_character_range指定minimum/maximum。P01—P06 的编辑和文风验读不增加事实审计、评分或检测门控。

新任务沿用[2026-10-11已选文风例文](resources/selected_pattern_examples_20261011/README.md)：P01原两篇，P02—P06各一篇，不补第二篇；全文进入蓝图、作者和全文编辑，原有例文替换与A/B入口保留。六类全部纯文字，无图片、图注或配图占位。建议篇幅依次为P01 3000—3600、P02 2200—3000、P03 3500—4500、P04 2200—3000、P05 3500—4500、P06 4500—5500个正文可见字符，明确的本篇要求优先。历史冻结任务不自动改变。

实际写作过程见任务内reviews/article_process.html，只展示稿件与编辑结果，无额外摘要模型调用。


## v16.8.2 P0 蓝图补料修复

新建 P0 的蓝图选材只继承用户明确的持久要求与本轮蓝图修改，旧模型候选的 article_brief 不自动成为当前委托。补料后从真实原件重新选材；文章阶段继续读取已确认蓝图。例文保持本阶段不读取、第三遍载入星源智与港隽两篇完整原文。P01—P06 的 v16.8 写作和标题规则不变。

任务以新标记冻结本行为；没有该标记的历史请求与旧发行包保持原构造，不修改已付费尝试。已有 16.8.1 Job 可在原蓝图页用原 revision 和显式 --p0-blueprint-edits 提交真实业务修改，重新预览后再确认；这不升级包，也不是重试。

真正接受蓝图时，新标记任务在原确认记录中冻结该版写作要求和蓝图SHA。后续重新规划把它作为独立的已确认业务上下文，保留未改变的范围/篇幅/排版，明确新修改优先；未批准的新候选不替换这份上下文，也不成为用户委托或事实来源。


## P0 选用事实传递

新建 P0 在初稿、E8、文风编辑、全文编辑意见与返工中传递同一份选用事实。全文编辑同时检查稿件与材料的一致性，扩写意见须指向材料已有内容；作者不把通用方法写成企业实际采用的步骤、协作、服务或效果。任务以 `p0_selected_facts_mode=selected-facts-v1` 冻结该输入，历史无标记请求保持原文。现有阶段、模型和一次编辑返工流程保留。
