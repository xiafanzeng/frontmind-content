# FrontMind Final v10 旧稿编辑规则切换修复

## 实际问题

v8/v9 为新建问题文章接入了正文和定位编辑规则。此前已完成的旧 Job 仍保留历史合同，这是为了避免改写已有请求身份。然而，仅给这些旧任务传入新的改稿委托，并不会启用新规则。实际请求仍把旧蓝图中的面诊清单当作业务边界，在当前修改意见后添加“不要从头重写”“局部精修”等旧指示。本轮真实运行中，DeepSeek E8 与宿主虽作了修改，正文仍然明显偏向核验指南。

上述指令存在拉扯，是可以核实的执行问题；它不证明模型必然无法遵循当前委托，也不能将文风差异单独归因于模型品牌。

## 修改范围

新增 continue 参数 `--upgrade-article-editor`，只用于已完成问题文章的显式新正文改稿。控制器依次执行真实来源检查、旧 Job 完整快照、记录合同切换、冻结当前改稿委托、新 E8 与终审请求。旧 prompt、checkpoint、结果及蓝图不改写，原始初稿不重跑。切换后的合同是现有 `frontmind-article-positioning/4.13.2-final9`，没有新增模型、评分、自动付费循环或确认节点。

旧 Job 不带参数时保持原行为。P0 禁止使用该参数。单独使用、和标题修改等动作混用、版本过期或来源校验不通过时，在变更任务前拒绝。配置、最大额度、408/响应流恢复和备用模型均保持原值。

## 使用

在已完成的问题文章中，将用户当前意见和点名原句完整保存为 UTF-8 文件，再执行：

```sh
./scripts/frontmind continue --job-dir /absolute/job --revision CURRENT --manuscript-edits /absolute/edits.md --upgrade-article-editor
```

这是一次新的正式改稿，不是旧断点的原位换规则。不要手动加写 metadata。正常断点恢复仍使用原来的 continue 入口。

## 验证

796 项回归测试通过；官方 OpenAI Agents SDK 的 4 项离线集成测试通过且无跳过。显式升级、完整快照、旧合同兼容、错误参数不变更任务、P0 隔离与实际请求分支均已覆盖。测试均不调用付费接口。

结构测试证明来源检查、快照、显式切换及请求分支工作正常；真实文章是否适合发布，仍须逐篇阅读最终正文。运行成功与文稿质量达标是两件事。
