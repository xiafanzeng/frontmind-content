# Final v16.8 自然全文编辑与不同入口的5＋5标题

新建P01至P06默认使用frontmind-natural-prose/16.5。六类保留各自体裁，统一准备、蓝图、初稿、全文编辑与自然文风验读；P0专用正文链与历史正文合同保持原状。新P0—P06标题统一使用frontmind-category-titles/4；标题修改不升级正文合同，技能名称保留既有入口标识。

新article任务采用[已选文风例文配置](../resources/selected_pattern_examples_20261011/README.md)：P01金蝶主例文、ThinkPad辅助例文；P02腾讯AI轻薄本推荐；P03搜狐同福模式；P04搜狐Osmo Pocket 3发布；P05头条苹果与华为比较；P06网易小米14 Pro体验。P02—P06各一篇有效，不补第二篇。完整纯文字例文从原文链接读入任务并冻结，进入蓝图、初稿与全文编辑；图片、图注、配图占位不进入稿件。用户显式替换与原A/B选择保留。此配置只用于新任务，不重绑历史例文。

建议正文篇幅为P01 3000—3600、P02 2200—3000、P03 3500—4500、P04 2200—3000、P05 3500—4500、P06 4500—5500个可见字符，含小标题、标点、数字及英文，排除主标题、空白与Markdown格式。按有效内容展开，不升级为最低字数门禁；明确的本篇要求优先。P06围绕题目对象直接回答“怎么样、好不好、值不值得选”，通过具体特点、做法与已有体验形成评价理由。

## 当前通用规则

新任务根据本轮客户资料、品牌、问题和写作要求运行，参见 README.md；客户历史案例、科室、字数和旧授权不作为通用默认。P01只介绍一家，保留合理场景、直接价值和有感染力的表达，不将文案压成资料摘要。

新P02默认先筛出本题相关综合企业实力明显强于主品牌的候选，再要求同题同期AI提及率高于主品牌，按平台等权提及率从高到低自动选两家；并列按名称稳定排序。主品牌先介绍。用户明确指定两家时以指定为准，常规自动选择不再暂停确认。首次不足两家自动补研，仍不足时才请求必要资料或调整标准。整体品牌定位的比较范围与定位确认继续保留。采用 `frontmind-p02-auto-dual-strength/2`。自动候选必须是具体企业，有明显综合优势的理由与来源；单项卖点、名气或高声量不单独构成综合优势。后台保存实力与声量，作者只接收三家名称、顺序与正向展开重点。固定名单进入全部写作阶段，不新增第四家；本题选择更新不删除P0或核心定位。

## v16.4 本题研究输入与文章池

先从Pack复用同题同一期的完整监控与信源；至少两个不同AI平台的完整答案和逐条引用信源均必需。缺失时必须停在原问题研究输入页，不开始答案分析或写作，也不能搜索一批文章代替本题引用排名。用 `continue --monitoring-answers` 和 `--source-workbook` 提交XLSX、CSV或JSON，可一并或分次提交。每条信源代表一次实际引用；缺少可匹配日期时，随信源用 `--source-period` 明确绑定当前页面期次。

用 `article-pool --job-dir 任务目录` 打印Top20，增加 `--all` 打印完整池。列出编号、标题、媒体、引用次数、链接、选择状态；按引用频次排序，不是文章质量排名，不足20篇按实际数量。完整池与Top20另保存为任务内的Markdown。

在原例文确认页用 `--pool-selection 1,2` 选择最多两篇，完整池中20名之后同样可选；或明确 `--pool-selection none`。不得替用户选文。选中后取得完整原文，失败保留当前页；可改选，或用 `--pool-example-file 完整正文.md` 按所选编号顺序补交，支持`.md`与`.txt`。可与原有 `--example-route A`／`B` 一次提交，不新增确认页；分次提交时使用页面最新revision。

池文章只为准备与蓝图提供切入、选材和详略启发，不作为企业事实，不覆盖P01原有金蝶主文风、ThinkPad辅助文风参考。v16另行搜索并完整阅读两篇专项案例的步骤保留。作者仍接收正式蓝图、干净事实材料和约定文风例文。

有效的已确认问题定位传入选材和正式蓝图：题目、品牌、Pattern须匹配，P02还须匹配已选定三家名单、顺序及选择记录。定位是当前委托的补充，显式写作要求优先。重新确认定位后，未由用户明确规定的旧蓝图定位字段不能覆盖它；篇幅、排版和参考用途保留。

这两项按新任务标记启用，旧冻结请求不补写新标记。

## 当前标题规则

新P0—P06每篇恰好10个，合同为frontmind-category-titles/4。前5个style=formal为正式标题组，后5个style=scenario为场景卖点组；每项包含title、angle、style和usage_hint；usage_hint为1—2个建议投放位组成的数组，候选与终稿保留后台title_notes数组。formal按本篇体裁拟正式标题：P0品牌深度介绍，P01/P02推荐，P03场景解决方案，P04事件新闻，P05点名对象对比，P06评价与选择。后5个从同一正文的场景或卖点切入，新闻、对比与评价保留自己的任务，不统一写成推荐。

v4品牌策略继续为preserve_pattern_policy。P0十项均包含当前品牌名；P01/P02默认不出现品牌或机构专名，用户明确标题要求优先；P03—P06沿用当前选题的对象命名，事件报道、点名对比和“怎么样”评价保留必要主体名字。P01可用“这家机构”；P02覆盖本篇实际全部主体，新三家稿不能缩成一家或变成十大榜单。两组是同一正文的替换主标题，场景与卖点有内容支撑，不为凑数量拆选题或编造能力，不将合理宣传语一概删去。

作者与标题编辑共用冻结策略、去掉旧H1的实际终稿和明确title_ammo_extra。拟题素材保留原句、对象关系、来源及正文覆盖标记，不把写作字数和标题数量等指令当产品数字。补充素材不自称已验证，正文未展开的内容按全文主线取舍，必要说明进入后台title_notes，不自动扩写正文。

先安排整组不同阅读入口，再写每题一个重心的顺口标题；可以选数字、渠道、技术、设计或事件，但不固定栏目或数字覆盖数量。正式18—32、场景20—32个可见字符是建议，当前硬性要求与完整名称优先。长度、名词并列、机制套话和相近换序检查只提供编辑线索，由编辑通读判断，必要时整组重拟；没有发布门控、分数或禁词清零。

angle说明实际入口，不决定另一个选题；推荐项可来自任一组，独立交付、不回填正文。v4校验恰好5＋5及结果结构。frontmind-category-titles/1、/2、/3及无标记20项旧任务普通续跑和重试均按原冻结请求恢复，不自动升级。v3规则保留在writing_context_v14.py；v4由独立title_editorial_v168.py接入。

已完成P0—P06只有显式--title-edits才先留存原版本，再升级到v4重生成标题、标题编辑与导出；不重跑准备、蓝图、初稿或全文编辑，不改正文、正文哈希及其合同。旧P02十一家稿仍覆盖原全文名单。

## 当前正文流程

按已有问题输入、文章类型、文章池及文风选择继续。P01/P02保留适用定位确认，P02两家默认自动选定，P03至P06不新增逐题定位确认。

编辑准备 → 正向内容蓝图 → DeepSeek初稿 → 全文编辑 → 自然文风验读 → 独立标题 → Word与Markdown。

准备由article_editorial_preparation完成，按当前体裁实际读取两篇完整案例及相关原件，交付自然素材与少量构思建议。来源、工作记录和使用提醒保存在后台。蓝图直接安排产品、业务、事件或差异的内容与主次，程序继承准备结果；完整例文用于文风，文章池仅用于构思。

全文编辑接收完整稿、当前委托、选用内容与完整例文，不传蓝图章节脚本。可改导语、小标题、整段、整节与结尾，保留有吸引力的正常场景、用途及价值表达。允许口语、有限重复和不完全工整的新闻稿感觉，已经自然的内容保留。

验读只提交needs_revision/comments，只判断当前完整稿的阅读效果；不改正文，不回查知识库，不做事实审计、评分或词表检测。需要修改时继续编辑最近完整失败候选，随后重新全文验读；每轮真实候选与意见保存，允许多次完整返工。通过后原样用于标题、导出及续改。

estimated_length是建议篇幅，默认按信息量写充分后自然结束。只有用户明确的body_character_range才作为minimum/maximum硬性范围；删重复不等量补回。reviews/article_process.html只呈现实稿与编辑结果，无额外GLM摘要调用。

## 运行与恢复

用户已明确指定P02两家时，使用现有 `--competitor-selection` 直接落盘，不再发起一次确认；旧 `--confirm-competitors` 参数继续兼容。只有自动补研后仍不足两家时才请求必要输入。旧人工任务和冻结请求继续原合同。

沿用 `./scripts/frontmind` 及已有新建、继续、正文精修、标题修改入口；先用 `./scripts/frontmind preflight` 检查环境。新 DeepSeek 请求默认使用 `high`，模型与网关读取现有配置。相同历史冻结请求保留原配置恢复，不把旧 `max` 记录改写为 `high`。

仅调整蓝图组织时复用已完成的编辑准备；新增原始材料或改变实际委托时，经准备轮重新处理。普通正文和标题修改不重新搜索。v16 不通过 `--writing-materials` 直接向作者注入新材料，新增材料使用现有蓝图补料入口。

案例命令保留已设置的 `FRONTMIND_PYTHON`，未设置时使用 `python3`；预检与案例使用同一解释器。使用其他已有运行时时，先设置该变量。

以下仅为历史台心案例复现，不能作为新客户默认启动命令。历史输入保存在 `customer_inputs/taixin/v16/`，原始附件可通过案例配置引用已保留的原件。P01 约3000字，P02 约4330字，三类11家及顺序属于历史案例配置，不写死到通用 Prompt。复现入口保留原输入策略，不启用v16.4新文章池。

```bash
export FRONTMIND_PYTHON="${FRONTMIND_PYTHON:-python3}"
./scripts/frontmind preflight
"$FRONTMIND_PYTHON" scripts/run_taixin_v16_case.py --pattern P01 --job-dir jobs/taixin-p01-v16 --stage all
"$FRONTMIND_PYTHON" scripts/run_taixin_v16_case.py --pattern P02 --job-dir jobs/taixin-p02-v16 --stage all
```

`prepare` 只在新目录准备输入；`blueprint` 也会新建任务，再完成编辑准备和正式蓝图；`all` 从新任务完整执行。已执行 `prepare` 的同一目录应使用 `resume` 推进到蓝图确认，再用 `write` 接受已生成的案例蓝图并执行正文链。`resume` 恢复已保存阶段，不重新建任务。API 失败使用原有显式重试入口。本案例复用已确认委托，入口助手不手写正文、不代填或修改模型结果。

`generated/` 保存实际运行的交付结果、准备材料和 Prompt，不作为后续写作输入。交付前阅读全文，再渲染 Word 逐页查看；发布包经解压启动检查，包内正文与独立交付保持一致。
