# v16.25.1 两阶段工作流接入

新任务冻结 `16.25.1 / native_content_v2 / two_stage_v16251`。现有已冻结任务保留原 ZIP、状态格式、模型、确认和恢复逻辑；不对既有任务或资料包做静默升级。

## 输入、执行与交付

- 第一阶段从完整 Markdown 知识库 ZIP 整理定位，等待具体定位选择，再整理优势并等待增删和排序确认。三项 Pack 在优势确认后立即交付。
- 已有 Pack 可从第一栏显式导入，沿用本包确认内容。Pack 固定为 `定位.md`、`核心差异化优势.md`、`知识库.zip`，知识库 ZIP 字节保留。
- P0 可使用确认 Pack 单独制作。第二阶段直接使用 Pack 选题写作，P0 不作为前置条件或事实输入。
- 第二阶段分别保留问题、回答状态、信源、问题类型/文章模式、本篇任务、简要约稿的具体选择。已明确提供的题目和有角色标记的输入文件直接传入，不重复索取。
- P01/P02/P03/P04/P06 分别进入对应作者角色。P02 从确认同类池选择本篇子集，不固定两家；新版没有 P05。旧任务的 P05 合同保持可读、可恢复。
- Kimi Hosted `kimi-k3.1-pro/high` 分析、选材、文风核对、媒体推荐和页图验收；XTY `gemini-4-argon/high` 写作、必要轻润色、拟 10 个标题。两个业务引擎使用 HTTP，不用旧工作流的 SDK/DeepSeek 写作链。
- 成稿只做一次文风检查，有具体问题才轻润色一次，再确认原问题。不增加事实核验、评分或多轮全文改写。
- Top20 文章参考池与最多 20 个独立信源推荐分别计算。推荐表固定四列，保留完整候选/剔除清单和实际 Prompt、返回、公开操作事件。
- Word 先由现有沙箱的 LibreOffice/Poppler 实际渲染全部页，再提交实际 PNG 给 Kimi 检查；文件导出不等于视觉通过。

应用入口为 `source/scripts/frontmind_v16251.py`。它只编排两个原业务引擎，写应用状态投影和真实用户审阅页；原引擎的项目文件、版本、确认、请求、返回保存在同一个持久 Job 中。状态采用独立 `16.25.1` 格式，不伪装成旧 `4.11`。

## 供应商与恢复

复用现有 Agent Runner 的任务、快照、私有资产和 egress，不增加第二套服务。`native_content_v2` 的模型路由独立于历史 `native_content_v1`。Kimi 的文件、Session、artifact 按实际创建它们的任务隔离；禁止读取其他任务、枚举全局文件、换目标域名或修改模型/强度。共享 Agent/Environment 定义发生变化时停止，不静默重绑。

Runner 私有环境配置以下值，不放入源码、浏览器或沙箱：

- `CONTENT_WORKFLOW_XTY_API_KEY`：沿用既有 XTY 配置；仍可使用原 `XTY_API_KEY` 回退。
- `CONTENT_WORKFLOW_KIMI_API_KEY`
- `CONTENT_WORKFLOW_KIMI_AGENT_ID`
- `CONTENT_WORKFLOW_KIMI_ENVIRONMENT_ID`

模型、API 版本和 HTTP 目标由代码固定。包内配置只留空 Key 和非秘密占位标识；真实认证由宿主代理注入。Hosted 的累计用量按 Session 增量记录，轮询和恢复不重复累加。

等待时续查同一已派发请求。失败或结果未知保留记录，不自动付费重发、换模型或创建替代 Session。恢复一个已经处于用户暂停或已交付状态的 Job 时，仅回传实际状态，不推进业务。

## 资料包登记

宿主读取实际 ZIP 字节，检查三个成员、嵌套知识库、路径、大小、品牌/别名和哈希，再与同账号/项目/聊天/任务/operation 的状态及产物证据交叉核对。新版登记 `packFormat=three_item_v16251`，不会伪造旧 `4.1` manifest 或 P0 完成标志。旧包没有该标识，不能仅改页面标签后被当作新格式继续。

新建和显式导入不会用当前旧 Pack 替换用户上传文件；当前版本号仅用作并发基线。新问题文章可使用尚未包含 P0 的已确认三项 Pack。旧文章的绑定版本保持不变。
